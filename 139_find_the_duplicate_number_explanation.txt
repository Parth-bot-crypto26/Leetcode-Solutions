===================================================================
LEETCODE 287: FIND THE DUPLICATE NUMBER
===================================================================

[PROBLEM DESCRIPTION]
Given an array of integers 'nums' containing n + 1 integers where each integer is in the range [1, n] inclusive.
There is only one repeated number in nums, return this repeated number.

You must solve the problem:
1. Without modifying the array 'nums'.
2. Using only constant extra space $O(1)$.
3. In linear runtime complexity $O(n)$.

Constraints:
- 1 <= n <= 10^5
- nums.length == n + 1
- 1 <= nums[i] <= n

-------------------------------------------------------------------
[METHODOLOGY: FLOYD'S TORTOISE AND HARE (CYCLE DETECTION)]
-------------------------------------------------------------------

Your C++ implementation is optimal!

1. LINKED LIST CYCLE EQUIVALENCE:
   - Treat each index `i` as a node in a linked list where the directed edge points to `nums[i]`.
   - Because all values are in $[1, n]$, every node points to a valid index in the array.
   - Since there are $n + 1$ elements but values are only up to $n$, at least two indices point to the same next index, creating a cycle. The entrance to this cycle is the duplicated number.

2. TWO-PHASE DETECTION (FLOYD'S ALGORITHM):
   - Phase 1 (Find Intersection): Move `slow` by 1 step (`nums[slow]`) and `fast` by 2 steps (`nums[nums[fast]]`) until they meet inside the cycle.
   - Phase 2 (Find Cycle Entrance): Reset `slow` to `nums[0]`. Move both `slow` and `fast` 1 step at a time until they meet again. Their point of intersection is the start of the cycle, which corresponds to the repeated value.

3. PROOF OF DUPLICATE EXISTENCE (PIGEONHOLE PRINCIPLE):
   - Putting $n + 1$ items (pigeons/array elements) into $n$ containers (holes/range $[1, n]$) guarantees that at least one container must hold more than one item.

-------------------------------------------------------------------
[DRY RUN EXAMPLE]
-------------------------------------------------------------------
Input: nums = [1, 3, 4, 2, 2] | n = 4

- Phase 1: Detect Intersection Point
  * Start: slow = nums[0] = 1, fast = nums[0] = 1
  * Iteration 1: slow = nums[1] = 3, fast = nums[nums[1]] = nums[3] = 2 (slow != fast)
  * Iteration 2: slow = nums[3] = 2, fast = nums[nums[2]] = nums[4] = 2 (slow == fast)
  * Intersection found at index/value 2.

- Phase 2: Find Entrance to Cycle
  * Reset slow = nums[0] = 1
  * Iteration 1: slow = nums[1] = 3, fast = nums[2] = 4 (slow != fast)
  * Iteration 2: slow = nums[3] = 2, fast = nums[4] = 2 (slow == fast)
  * Loop terminates. Entrance node is 2.

Returns 2.

-------------------------------------------------------------------
[C++ CODE IMPLEMENTATION]
-------------------------------------------------------------------

class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        int slow = nums[0];
        int fast = nums[0];
        
        // Phase 1: Locate the intersection point in the cycle
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);
        
        // Phase 2: Locate the entrance to the cycle
        slow = nums[0];
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        
        return slow;
    }
};

-------------------------------------------------------------------
[COMPLEXITY ANALYSIS]
-------------------------------------------------------------------

Time Complexity: O(n)
- Explanation: The `fast` pointer traverses the loop at double speed, meeting `slow` in $O(n)$ steps. Phase 2 traverses at most $n$ additional steps to find the entry point.

Space Complexity: O(1)
- Explanation: Uses only two scalar integer pointers (`slow` and `fast`) without modifying the input array.
