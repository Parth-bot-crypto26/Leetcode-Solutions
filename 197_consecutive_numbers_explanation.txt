===================================================================
LEETCODE 180: CONSECUTIVE NUMBERS
===================================================================

[PROBLEM DESCRIPTION]
Find all numbers that appear at least three times consecutively in the `Logs` table.
Return the result table in any order, with the column named `ConsecutiveNums`.

Constraints & Notes:
- `id` is the primary key and an auto-incrementing column starting from 1.
- `num` is a varchar.
- "Consecutively" means adjacent rows by `id` (e.g., id = 1, id = 2, id = 3).

-------------------------------------------------------------------
[METHODOLOGY & CRITIQUE OF YOUR APPROACH]
-------------------------------------------------------------------

Your SQL implementation using window functions is 100% optimal and extremely clean!

1. WINDOW FUNCTIONS (`LEAD`):
   - `LEAD(num, 1) OVER (ORDER BY id)` fetches the value of `num` from the very next row.
   - `LEAD(num, 2) OVER (ORDER BY id)` fetches the value of `num` from two rows ahead.

2. FILTERING & DEDUPLICATION:
   - The `WHERE` clause (`num = next_num AND num = next_next_num`) checks if the current row's number matches both subsequent rows.
   - `SELECT DISTINCT` ensures that if a number appears consecutively 4 or more times, it is only returned once in the final result table.

3. ALTERNATIVE APPROACHES:
   - Traditional Self-Joins (`FROM Logs l1 JOIN Logs l2 ON l1.id = l2.id - 1 JOIN Logs l3 ON l1.id = l3.id - 2`) achieve the same result but are generally slower and less readable than window functions.

-------------------------------------------------------------------
[DRY RUN EXAMPLE]
-------------------------------------------------------------------
Input: 
Logs Table:
+----+-----+
| id | num |
+----+-----+
| 1  | 1   |
| 2  | 1   |
| 3  | 1   |
| 4  | 2   |
| 5  | 1   |
| 6  | 2   |
| 7  | 2   |
+----+-----+

Subquery Evaluation (`LEAD` window functions):
- id = 1: num = 1, next_num = 1, next_next_num = 1 -> MATCH (`1 = 1 AND 1 = 1`)
- id = 2: num = 1, next_num = 1, next_next_num = 2 -> NO MATCH
- id = 3: num = 1, next_num = 2, next_next_num = 1 -> NO MATCH
- id = 4: num = 2, next_num = 1, next_next_num = 2 -> NO MATCH
- id = 5: num = 1, next_num = 2, next_next_num = 2 -> NO MATCH
- id = 6: num = 2, next_num = 2, next_next_num = NULL -> NO MATCH
- id = 7: num = 2, next_num = NULL, next_next_num = NULL -> NO MATCH

Filtering & Distinct:
- Matched `num`: 1
- `SELECT DISTINCT` returns `1`.

Output:
+-----------------+
| ConsecutiveNums |
+-----------------+
| 1               |
+-----------------+

-------------------------------------------------------------------
[SQL & PANDAS IMPLEMENTATIONS]
-------------------------------------------------------------------

-- SQL Solution (Your Code - Optimal & Clean)
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT
        num,
        LEAD(num, 1) OVER (ORDER BY id) AS next_num,
        LEAD(num, 2) OVER (ORDER BY id) AS next_next_num
    FROM Logs
) sub
WHERE num = next_num AND num = next_next_num;


# Equivalent Pandas Solution (for LeetCode Pandas track)
import pandas as pd

def consecutive_numbers(logs: pd.DataFrame) -> pd.DataFrame:
    # Ensure rows are ordered by id
    logs = logs.sort_values(by='id')
    
    # Check if current num equals the next and the one after next
    logs['next_num'] = logs['num'].shift(-1)
    logs['next_next_num'] = logs['num'].shift(-2)
    
    mask = (logs['num'] == logs['next_num']) & (logs['num'] == logs['next_next_num'])
    
    # Extract unique matching numbers
    result = logs[mask]['num'].unique()
    
    return pd.DataFrame({'ConsecutiveNums': result})

[COMPLEXITY ANALYSIS]
-------------------------------------------------------------------

- Time Complexity: O(N log N)
  - Sorting the `Logs` table by `id` to evaluate the `LEAD` window function takes $O(N \log N)$ time.

- Space Complexity: O(N) Auxiliary Space
  - Space required by the database engine to store window frame partitions and intermediate subquery results.
