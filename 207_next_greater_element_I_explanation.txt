===================================================================
LEETCODE 496: NEXT GREATER ELEMENT I
===================================================================

[PROBLEM DESCRIPTION]
The next greater element of some element `x` in an array is the first greater 
element that is to the right of `x` in the same array.

You are given two distinct 0-indexed integer arrays `nums1` and `nums2`, where 
`nums1` is a subset of `nums2`. For each element in `nums1`, find its next greater 
element in `nums2`. If none exists, return `-1` for that query.

Constraints & Notes:
- `1 <= nums1.length <= nums2.length <= 1000`
- `0 <= nums1[i], nums2[i] <= 10^4`
- All integers in `nums1` and `nums2` are unique.
- Follow-up: Could you find an $O(\text{nums1.length} + \text{nums2.length})$ solution?

-------------------------------------------------------------------
[METHODOLOGY & CRITIQUE OF YOUR APPROACH]
-------------------------------------------------------------------

Your C++ implementation is **100% optimal, beautifully structured, and hits the $O(N + M)$ follow-up target!**

1. MONOTONIC STACK (RIGHT-TO-LEFT TRAVERSAL):
   - By traversing `nums2` from right to left, you maintain a decreasing stack of future candidates.
   - Any stack element smaller than or equal to the current element is popped because it can never be the next greater element for any element to its left.

2. HASH MAP O(1) LOOKUP:
   - You store the precomputed next greater result for every element of `nums2` in an `unordered_map`.
   - Finally, building the answer vector for `nums1` takes $O(\text{nums1.length})$ time via constant-time map lookups.

-------------------------------------------------------------------
[DRY RUN EXAMPLE]
-------------------------------------------------------------------
Input: nums1 = [4, 1, 2], nums2 = [1, 3, 4, 2]

1. Traverse `nums2` from right to left (indices 3 down to 0):
   - i = 3 (val = 2): Stack is empty. `mp[2] = -1`. Push `2`.
   - i = 2 (val = 4): Stack top is 2 ($\le 4$) -> pop 2. Stack is empty. `mp[4] = -1`. Push `4`.
   - i = 1 (val = 3): Stack top is 4 (> 3). `mp[3] = 4`. Push `3`.
   - i = 0 (val = 1): Stack top is 3 (> 1). `mp[1] = 3`. Push `1`.
   
   Map state: `{2: -1, 4: -1, 3: 4, 1: 3}`

2. Query `nums1`:
   - For 4: `mp[4]` = -1
   - For 1: `mp[1]` = 3
   - For 2: `mp[2]` = -1

Final Output: `[-1, 3, -1]`

-------------------------------------------------------------------
[C++ & PYTHON IMPLEMENTATIONS]
-------------------------------------------------------------------

// C++ Solution (Your Code - Optimal Monotonic Stack + Hash Map)
#include <vector>
#include <unordered_map>
#include <stack>

class Solution {
public:
    std::vector<int> nextGreaterElement(std::vector<int>& nums1, std::vector<int>& nums2) {
        std::unordered_map<int, int> mp;
        std::stack<int> s;
        
        // Precompute next greater elements for nums2 from right to left
        for (int i = nums2.size() - 1; i >= 0; i--) {
            while (!s.empty() && s.top() <= nums2[i]) {
                s.pop();
            }
            if (s.empty()) {
                mp[nums2[i]] = -1;
            } else {
                mp[nums2[i]] = s.top();
            }
            s.push(nums2[i]);
        }
        
        // Map back to nums1
        std::vector<int> ans;
        for (int i = 0; i < nums1.size(); i++) {
            ans.push_back(mp[nums1[i]]);
        }
        
        return ans;
    }
};


# Equivalent Python Solution
class Solution:
    def nextGreaterElement(self, nums1: list[int], nums2: list[int]) -> list[int]:
        mp = {}
        stack = []
        
        for num in reversed(nums2):
            while stack and stack[-1] <= num:
                stack.pop()
            mp[num] = stack[-1] if stack else -1
            stack.append(num)
            
        return [mp[num] for num in nums1]

-------------------------------------------------------------------
[COMPLEXITY ANALYSIS]
-------------------------------------------------------------------

- Time Complexity: O(N + M)
  - Where `N` is the length of `nums2` and `M` is the length of `nums1`. Each element in `nums2` is pushed and popped from the stack at most once, and map lookups take $O(1)$ average time.

- Space Complexity: O(N) Auxiliary Space
  - Space required for the hash map and stack to store elements of `nums2`.
