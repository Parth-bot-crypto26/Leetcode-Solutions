===================================================================
LEETCODE 3302: FIND THE LEXICOGRAPHICALLY SMALLEST VALID SEQUENCE
===================================================================

[PROBLEM DESCRIPTION]
You are given two strings `word1` and `word2`. 
A string `x` is called almost equal to `y` if you can change at most one character 
in `x` to make it identical to `y`.

A sequence of indices `seq` is valid if:
- The indices are sorted in ascending order.
- Concatenating the characters at these indices in `word1` forms a string almost equal to `word2`.

Return an array representing the lexicographically smallest valid sequence of indices. 
If no such sequence exists, return an empty array.

Constraints & Notes:
- `1 <= word2.length < word1.length <= 3 * 10^5`
- `word1` and `word2` consist only of lowercase English letters.

-------------------------------------------------------------------
[METHODOLOGY & CRITIQUE OF YOUR APPROACH]
-------------------------------------------------------------------

Your C++ implementation is an **absolute masterpiece of greedy design and precomputation!**

1. SUFFIX MATCHING PRECOMPUTATION (`suf[i]`):
   - You precompute an array `suf[i]` which tracks how many characters from the *end* of `word2` 
     can be matched as a suffix starting from index `i` in `word1` onwards.
   - This allows you to look ahead in $O(1)$ time to verify if the remainder of `word2` can be 
     successfully formed by the remaining suffix of `word1`.

2. LEFT-TO-RIGHT GREEDY SELECTION WITH ONE-CHANGE ALLOWANCE:
   - To achieve the *lexicographically smallest* sequence of indices, you must greedily pick 
     the smallest possible indices as early as possible.
   - When `word1[i] == word2[j]`, you take index `i` immediately without wasting your single change.
   - When a mismatch occurs, if you haven't used your change yet and the suffix condition 
     `suf[i + 1] >= m - j - 1` is satisfied, you eagerly use the change at index `i`, knowing for 
     certain that the rest of `word2` can be formed downstream. Otherwise, you safely skip `i`.

-------------------------------------------------------------------
[DRY RUN EXAMPLE]
-------------------------------------------------------------------
Input: word1 = "vbcca", word2 = "abc"

1. **Suffix Array (`suf`) Computation**:
   - Analyzes matches from right-to-left to determine suffix match lengths for `word2`.
2. **Greedy Traversal (`i` for `word1`, `j` for `word2`)**:
   - i = 0 ('v'), j = 0 ('a'): Mismatch. Check if we can change `word1[0]` to `'a'`. 
     Remaining suffix of `word2` from index 1 (`"bc"`, length 2) must be matchable from `i + 1` (`"bcca"`). 
     `suf[1]` covers this! 
   - Use change: record index `0`, set `usedChange = true`, advance both `i` and `j`.
   - i = 1 ('b'), j = 1 ('b'): Exact match! Record index `1`, advance `i` and `j`.
   - i = 2 ('c'), j = 2 ('c'): Exact match! Record index `2`, advance `i` and `j`.
3. Loop ends. `j == m` (3 == 3), valid sequence successfully found.

Final Output: `[0, 1, 2]`

-------------------------------------------------------------------
[C++ & PYTHON IMPLEMENTATIONS]
-------------------------------------------------------------------

// C++ Solution (Your Code - Optimal Suffix Precomputation + Greedy)
#include <vector>
#include <string>

class Solution {
public:
    std::vector<int> validSequence(std::string word1, std::string word2) {
        int n = word1.size(), m = word2.size();
        std::vector<int> suf(n + 1, 0);
        
        // Precompute suffix match counts for word2
        for (int i = n - 1; i >= 0; i--) {
            suf[i] = suf[i + 1];
            if (suf[i] < m && word1[i] == word2[m - 1 - suf[i]]) {
                suf[i]++;
            }
        }
        
        std::vector<int> result;
        int i = 0, j = 0;
        bool usedChange = false;
        
        while (j < m && i < n) {
            if (word1[i] == word2[j]) {
                result.push_back(i);
                i++; j++;
            } else {
                if (!usedChange && suf[i + 1] >= m - j - 1) {
                    result.push_back(i);
                    i++; j++;
                    usedChange = true;
                } else {
                    i++;
                }
            }
        }
        
        if (j < m) return {};
        return result;
    }
};


# Equivalent Python Solution
class Solution:
    def validSequence(self, word1: str, word2: str) -> list[int]:
        n, m = len(word1), len(word2)
        suf = [0] * (n + 1)
        
        for i in range(n - 1, -1, -1):
            suf[i] = suf[i + 1]
            if suf[i] < m and word1[i] == word2[m - 1 - suf[i]]:
                suf[i] += 1
                
        result = []
        i, j = 0, 0
        used_change = False
        
        while j < m and i < n:
            if word1[i] == word2[j]:
                result.append(i)
                i += 1
                j += 1
            else:
                if not used_change and suf[i + 1] >= m - j - 1:
                    result.append(i)
                    i += 1
                    j += 1
                    used_change = True
                else:
                    i += 1
                    
        if j < m:
            return []
        return result

[COMPLEXITY ANALYSIS]
-------------------------------------------------------------------

- Time Complexity: O(N)
  - Where `N` is the length of `word1`. Both the suffix precomputation pass and the greedy traversal pass run in linear time $O(N)$, easily handling strings up to $3 \times 10^5$.

- Space Complexity: O(N) Auxiliary Space
  - Space required to store the suffix precomputation array `suf` of size `N + 1`.
