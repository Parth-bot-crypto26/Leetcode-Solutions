LEETCODE 3471: FIND THE LARGEST ALMOST MISSING INTEGER
===================================================================

[PROBLEM DESCRIPTION]
You are given an integer array `nums` and an integer `k`.
- An integer `x` is **almost missing** from `nums` if `x` appears in **exactly one** subarray of size `k`.
- Return the largest almost missing integer from `nums`. If no such integer exists, return `-1`.
- A subarray is a contiguous sequence of elements within an array.

Constraints & Notes:
- `1 <= nums.length <= 50`
- `0 <= nums[i] <= 50`
- `1 <= k <= nums.length`

-------------------------------------------------------------------
[METHODOLOGY & CRITIQUE OF YOUR APPROACH]
-------------------------------------------------------------------

Your C++ implementation is an **exceptionally clever, highly optimized, and completely correct solution!**

1. CASE-BASED LOGICAL BREAKDOWN:
   - **Case `k == n`**: There is only one possible subarray of size `k` (the entire array itself). Every unique element inside `nums` appears in exactly that single subarray. Therefore, the largest almost missing integer is simply the maximum element in `nums`. Your code handles this instantly.
   - **Case `k == 1`**: Each subarray has length 1 (i.e., individual elements). An element appears in exactly one subarray of size 1 if and only if its global frequency in `nums` is 1. Your code correctly isolates these elements using a frequency map and finds the maximum.
   - **General Case (`1 < k < n`)**: A profound property of subarrays of length $k$ is that any element that appears in only *one* subarray must be located at the absolute boundaries of the array—specifically, `nums[0]` or `nums[n - 1]`. Elements in the interior of the array are covered by multiple overlapping sliding windows of size $k$. Thus, you only need to check if `nums[0]` or `nums[n - 1]` has a window appearance count of 1.

2. EFFICIENCY:
   - Given the small constraints ($N \le 50$), your nested window scanning and boundary checks execute in well under a millisecond with negligible memory usage.

-------------------------------------------------------------------
[DRY RUN EXAMPLE]
-------------------------------------------------------------------
Input: nums = [3, 9, 2, 1, 7], k = 3 (n = 5)

- Since `1 < k < n` (3 < 5), we fall into the general case:
  - We slide a window of size 3 across `nums`:
    - Window 0: `[3, 9, 2]` -> unique elements: {3, 9, 2}
    - Window 1: `[9, 2, 1]` -> unique elements: {9, 2, 1}
    - Window 2: `[2, 1, 7]` -> unique elements: {2, 1, 7}
  - Accumulate how many windows each element appears in:
    - 3 appears in 1 window (`count[3] = 1`)
    - 9 appears in 2 windows (`count[9] = 2`)
    - 2 appears in 3 windows (`count[2] = 3`)
    - 1 appears in 2 windows (`count[1] = 2`)
    - 7 appears in 1 window (`count[7] = 1`)
  - Check boundaries:
    - `nums[0] = 3` has `count[3] == 1` $\to$ candidate max = 3.
    - `nums[4] = 7` has `count[7] == 1` $\to$ candidate max = max(3, 7) = 7.

Final Output: `7`

[C++ & PYTHON IMPLEMENTATIONS]
-------------------------------------------------------------------

// C++ Solution (Your Code - Optimal Case Analysis & Boundary Check)
#include <vector>
#include <unordered_map>
#include <unordered_set>
#include <algorithm>

class Solution {
public:
    int largestInteger(std::vector<int>& nums, int k) {
        int n = nums.size();
        if (k == n) {
            int max_val = -1;
            for (int x : nums) {
                max_val = std::max(max_val, x);
            }
            return max_val;
        }
        
        if (k == 1) {
            std::unordered_map<int, int> count;
            for (int x : nums) {
                count[x]++;
            }
            int max_val = -1;
            for (auto& pair : count) {
                if (pair.second == 1) {
                    max_val = std::max(max_val, pair.first);
                }
            }
            return max_val;
        }
        
        std::unordered_map<int, int> count;
        for (int i = 0; i <= n - k; ++i) {
            std::unordered_set<int> unique_in_window;
            for (int j = 0; j < k; ++j) {
                unique_in_window.insert(nums[i + j]);
            }
            for (int x : unique_in_window) {
                count[x]++;
            }
        }
        
        int ans = -1;
        if (count[nums[0]] == 1) ans = std::max(ans, nums[0]);
        if (count[nums[n - 1]] == 1) ans = std::max(ans, nums[n - 1]);
        return ans;
    }
};


# Equivalent Python Solution
class Solution:
    def largestInteger(self, nums: list[int], k: int) -> int:
        n = len(nums)
        if k == n:
            return max(nums)
            
        if k == 1:
            counts = {}
            for x in nums:
                counts[x] = counts.get(x, 0) + 1
            max_val = -1
            for x, freq in counts.items():
                if freq == 1:
                    max_val = max(max_val, x)
            return max_val
            
        count = {}
        for i in range(n - k + 1):
            unique_in_window = set(nums[i:i + k])
            for x in unique_in_window:
                count[x] = count.get(x, 0) + 1
                
        ans = -1
        if count.get(nums[0], 0) == 1:
            ans = max(ans, nums[0])
        if count.get(nums[n - 1], 0) == 1:
            ans = max(ans, nums[n - 1])
            
        return ans

-------------------------------------------------------------------

- Time Complexity: O(N * K)
  - Where `N` is the length of `nums` and `K` is the subarray size. Building windows and extracting unique sets takes minimal operations for $N \le 50$.

- Space Complexity: O(N) Auxiliary Space
  - Storage required for frequency hash maps and window sets, scaling linearly with input size.
