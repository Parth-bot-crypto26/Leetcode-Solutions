===================================================================
LEETCODE 12: INTEGER TO ROMAN
===================================================================

[PROBLEM DESCRIPTION]
Seven different symbols represent Roman numerals with their respective values:
- `I = 1`, `V = 5`, `X = 10`, `L = 50`, `C = 100`, `D = 500`, `M = 1000`

Roman numerals are formed by appending the conversions of decimal place values from highest to lowest, 
incorporating subtractive forms where applicable (e.g., `4 = IV`, `9 = IX`, `40 = XL`, `90 = XC`, `400 = CD`, `900 = CM`).

Given an integer, convert it to a Roman numeral.

Constraints & Notes:
- `1 <= num <= 3999`

-------------------------------------------------------------------
[METHODOLOGY & CRITIQUE OF YOUR APPROACH]
-------------------------------------------------------------------

Your C++ implementation using a **greedy lookup table of value-symbol pairs** is **100% optimal, remarkably elegant, and textbook-perfect!**

1. GREEDY SUBTRACTION WITH SUBTRACTIVE COMBINATIONS:
   - By pre-populating a vector of pairs sorted in descending order of value—including standard subtractive forms like `"CM"` (900), `"CD"` (400), `"XC"` (90), `"XL"` (40), `"IX"` (9), and `"IV"` (4)—you completely eliminate complex conditional branching or digit-place parsing logic.
   - Iterating through the table and greedily subtracting the largest possible Roman value while appending its symbol constructs the exact correct Roman representation from highest to lowest place values.

2. EFFICIENCY:
   - Since the input is capped at `3999`, the number of subtraction steps is strictly bounded and extremely small, running in $O(1)$ time complexity with minimal memory footprint.

-------------------------------------------------------------------
[DRY RUN EXAMPLE]
-------------------------------------------------------------------
Input: num = 1994

- `valueSymbols` list starts with `{1000: "M"}, {900: "CM"}, {500: "D"}, {400: "CD"}, {100: "C"}, {90: "XC"}, {50: "L"}, {40: "XL"}, {10: "X"}, {9: "IX"}, {5: "V"}, {4: "IV"}, {1: "I"}`
- Iteration steps:
  - `{1000, "M"}`: `1994 >= 1000` -> appends `"M"`, `num` becomes `994`.
  - `{900, "CM"}`: `994 >= 900` -> appends `"CM"`, `num` becomes `94`.
  - `{90, "XC"}`: `94 >= 90` -> appends `"XC"`, `num` becomes `4`.
  - `{4, "IV"}`: `4 >= 4` -> appends `"IV"`, `num` becomes `0`.
- Loop finishes.

Final Output: `"MCMXCIV"`

-------------------------------------------------------------------
[C++ & PYTHON IMPLEMENTATIONS]
-------------------------------------------------------------------

// C++ Solution (Your Code - Optimal Greedy Lookup Table)
#include <vector>
#include <string>
#include <utility>

class Solution {
public:
    std::string intToRoman(int num) {
        std::vector<std::pair<int, std::string>> valueSymbols = {
            {1000, "M"}, {900, "CM"}, {500, "D"}, {400, "CD"}, 
            {100, "C"}, {90, "XC"}, {50, "L"}, {40, "XL"}, 
            {10, "X"}, {9, "IX"}, {5, "V"}, {4, "IV"}, {1, "I"}
        };
        
        std::string result = "";
        for (const auto& [value, symbol] : valueSymbols) {
            while (num >= value) {
                result += symbol;
                num -= value;
            }
        }
        return result;
    }
};


# Equivalent Python Solution
class Solution:
    def intToRoman(self, num: int) -> str:
        value_symbols = [
            (1000, "M"), (900, "CM"), (500, "D"), (400, "CD"),
            (100, "C"), (90, "XC"), (50, "L"), (40, "XL"),
            (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I")
        ]
        
        result = []
        for value, symbol in value_symbols:
            if num == 0:
                break
            count, num = divmod(num, value)
            result.append(symbol * count)
            
        return "".join(result)

[COMPLEXITY ANALYSIS]
-------------------------------------------------------------------

- Time Complexity: O(1)
  - The maximum value of `num` is 3999, meaning the outer loop executes a fixed number of times and inner loops iterate at most 3 or 4 times.

- Space Complexity: O(1) Auxiliary Space
  - Uses a fixed-size lookup vector and result string storing at most 15 characters, requiring constant extra memory.
