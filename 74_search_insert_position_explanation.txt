===================================================================
LEETCODE 35: SEARCH INSERT POSITION
===================================================================

[PROBLEM DESCRIPTION]
Given a sorted array of distinct integers 'nums' and a 'target' value, return the 
index if the target is found. If not, return the index where it would be if it 
were inserted in order.

Constraint: Must execute in strict O(log n) runtime complexity.

-------------------------------------------------------------------
[METHODOLOGY: BINARY SEARCH INVARIANT & INSERTION POINT CONVERGENCE]
-------------------------------------------------------------------

Because the input array is sorted and distinct, a linear search scanning $O(n)$ elements 
violates the explicit problem constraints. We implement a classic **Binary Search** pattern:

1. SAFE MIDPOINT CALCULATION:
   - We maintain search boundaries 'left = 0' and 'right = nums.size() - 1'.
   - The midpoint calculation 'mid = left + (right - left) / 2' prevents integer overflow 
     vulnerabilities associated with large coordinate sums.

2. SEARCH SPACE HALVING:
   - If 'nums[mid] == target', we found our target and return 'mid' immediately.
   - If 'nums[mid] < target', the target lies strictly to the right, so we set 'left = mid + 1'.
   - If 'nums[mid] > target', the target lies strictly to the left, so we set 'right = mid - 1'.

3. THE INSERTION INVARIANT:
   - If 'target' is not present in 'nums', the loop terminates when 'left > right'.
   - At this exact convergence state, 'left' holds the position of the first element greater 
     than 'target' (or 'nums.size()' if 'target' is greater than all elements). Thus, 'left' 
     is guaranteed to be the exact correct insertion index.

-------------------------------------------------------------------
[DRY RUN EXAMPLE]
-------------------------------------------------------------------
Input: nums = [1, 3, 5, 6], target = 2

Initial State: left = 0, right = 3

- Iteration 1:
  mid = 0 + (3 - 0) / 2 = 1
  nums[1] = 3. Since 3 > target (2), right = mid - 1 = 0.
- Iteration 2:
  mid = 0 + (0 - 0) / 2 = 0
  nums[0] = 1. Since 1 < target (2), left = mid + 1 = 1.

Loop Terminates (left = 1, right = 0 -> left > right).
Returns left = 1.

-------------------------------------------------------------------
[COMPLEXITY ANALYSIS]
-------------------------------------------------------------------

Time Complexity: O(log n)
- Explanation: Where 'n' is the length of the 'nums' array. At each iteration step, 
  the algorithm halves the remaining search space, executing in strict logarithmic time.

Space Complexity: O(1)
- Explanation: The operation runs entirely in-place, relying exclusively on scalar 
  pointer registers ('left', 'right', 'mid') on the stack frame.
